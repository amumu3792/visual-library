# 视觉知识库项目 · 长期约定

## 不可违反的硬性规则
1. **绝不做「网页内点按钮触发全量重写整库」的功能**。这类交互一点就坏（路径依赖 + 联网），用户已明确要求"扼杀"。更新知识库只走本地 bat 确定性重建。
2. **GPT 源文件路径一律多候选探测**（`_find_gpt_md()`），文件被挪到 `视觉资料库/GPT提示词库/` 等子目录也不许静默丢内容。
3. **两页统一用相对路径图片（kb_core 生成），绝不再 base64 内嵌**。base64 内嵌会把 `styles-overview.html` 撑到 26MB 并触发 `MemoryError`，把文件清空成 0 字节（2026-08-13 事故）。
4. **整理/重建永不删图片、永不删独有文档**，只做结构优化或移动归类。
5. **`styles-overview.html` 与 `design-knowledge-base.html` 都由 `kb_core.py` 统一生成**（`write_table_html()` + `write_merged_html()`）。**绝不再调用 `视觉资料库/sync-readme.py` 生成表格**（旧版、仍做 base64 内嵌，一跑就 `MemoryError`）。

## 两类"我的东西"——务必分清（2026-08-17 定案 + 同日重加）
知识库里"用户自己的内容"分两件**完全不同**的事，不要混淆、不要合并：

### A. 收藏已有卡片 = ⭐ 星标（浏览器本地，无需 md）
- 点卡片右上角 ⭐ 即收藏/取消，「我的收藏」筛选显示所有星标项（`FAV_KEY='kb_favorites_v1'`，localStorage）。
- 代价：清缓存 / 换浏览器 / 换设备会丢。要"永不丢"就让 ⭐ 写后端 `kb-manager.py` 持久化（不是复活 md 库）。

### B. 往库里新增提示词 = 暂存区 → 用户补充.md（本地 md 通道，与 ⭐ 完全分开）
- 用户要"往库里加新提示词"，⭐ 做不到（它只能给已有卡片打标）。这条通道是**真正加内容**。
- 入口：`视觉资料库/用户补充/暂存区.md`（收件箱，含使用说明+注释示例）。每条 `## 标题` 一个条目；图用 `![[url]]` 或 `![](url)`；提示词用三个反引号或 `提示词：` 行，或直接写一段文字（整段正文兜底）。
- 同步：双击 `同步本地.bat`/`同步GitHub.bat` → `kb_core.consume_staging()` 把**有效**条目搬进 `用户补充.md`（永久源）、**自动清空暂存区**、无效条目保留并附 `<!-- 跳过：… -->` 原因；`build_all()` 把用户新增并入 HTML，type=`用户新增`，网格有独立紫色徽章 + 「用户新增」筛选 chip。
- 远程图同步时由 `_download_user_image()` 落地本地（`视觉资料库/用户补充/图片/remote_*.png`），按文件头校验真图。
- **网页智能粘贴一键入库（2026-08-17 晚升级，同日再加管理面板）**：`kb-manager.py` 注入右下角「➕ 智能添加」浮窗，**一个框**粘入从别处复制来的整段（网站/AI工具/聊天记录），点「整理」调用 `POST /api/parse-entry` → 后端 `parse_raw_entry()` 启发式拆出 标题/提示词/图片（覆盖：markdown标题+代码块+![]图、标签式 标题：/提示词：/图片：、纯大段文字、Obsidian ![[url]]、无图）。**预览确认**（三格可改）→ 点「确认添加」`POST /api/add-entry`：写暂存区 → `consume_staging()` 搬进 `用户补充.md` → 重建两页 → 前端 `location.reload()`。即：不用记格式、不用手动分格、管它什么来源。**图片为可选**，留空只存文字+提示词；有图链接就自动下载落地本地。用户核心诉求："复制来的内容最长的是提示词、偶尔带网址，手动复制替换太低效"。`kb-manager.py` 的 `Handler.do_POST` 处理两接口，`INJECT_WIDGET` 是注入的浮窗 HTML/JS，`parse_raw_entry` 是核心拆分函数。
- **注意**：这是 2026-08-17 早先"删永久库"之后、用户又要"加新提示词"时**重新加回**的。旧 `remove_user_entry`/`rename_user_entry`/`MG_TOKEN`/管理登录 整套后端已删、不再加回（用户原话：永久收藏库多此一举）。但**用户新增条目可自由删除，且有两种入口**：① 卡片右上角 🗑（点 `deleteUserEntry` → `POST /api/delete-entry`）；② **「🗑 管理删除」浮窗**（左下浮动按钮 `mgrFab`，弹窗内按名称搜索 → 列出 `用户新增` 条目 → 点删除，直接命中用户诉求"按名称搜索删除某一个"）。后端均走 `remove_user_block()` 从 `用户补充.md` 抠掉 `## 标题` 块 → 重建两页。端到端已验证（添加→搜索→删除→0 残留）。**关键限制（用户常踩）**：🗑 与管理面板都只在**经「启动管理器.bat」以 http 打开**时才生效；直接双击 html 用 `file://` 打开，按钮虽可能在卡片上显示，但点下去会失败并提示"请通过启动管理器打开"。**内置风格/模板删除未做**：用户曾表达"总览全部内容都能管理"，但加错删自己的场景用用户新增删除已覆盖；若要做内置删除，用"排除列表"方式（隐藏+可逆+同步不复活），不物理删源文件。
- 排查顺序：加新提示词同步后看不到 → ① 黑窗口看 📥/⚠️ 报告（会直接告诉你哪条为什么没进）；② 确认加在 `暂存区.md` 且 `## 标题` 开头；③ 新增内容进融合库 `design-knowledge-base.html` 的「用户新增」筛选，不在表格页。

## bat 文件格式与逻辑铁律（2026-08-17，用户怒斥"bat 根本不能启动 / 不自动开浏览器"）
- **根因 1（启动不了）**：本环境 Write 工具写出的 `.bat` 默认是 Unix 换行（`\n`），缺 Windows 必需的 `CRLF`（`\r\n`）。双击 cmd 解析失败 → 齿轮图标 / 启动不了。
- **根因 2（启动管理器不弹浏览器）**：bat 直接调用 Python 起服务，服务 `serve_forever()` 阻塞，后面 `start "" url` 永远执行不到。
- **根因 3（同步 bat 弹不出网页）**：路径变量误写 `%%~dp0`（`%%` 只在 for 循环内转义），结果打开的是名为 `%%~dp0...` 的无效文件。
- **铁律**：任何 `.bat` 必须 **CRLF** 且无 UTF-8 BOM；写内容时 JSON 里显式用 `\r\n`；写完后字节级校验（CRLF > 0、LF_only = 0、无 BOM）。
- **启动管理器.bat 正确模板**：`start /b "" "python.exe" "%~dp0kb-manager.py"` 后台起服务 → `timeout /t 2 >nul` → `start "" "http://127.0.0.1:8137/..."` 打开浏览器。
- **同步 bat 正确模板**：`"python.exe" "%~dp0sync-xxx.py"` → `start "" "%~dp0design-knowledge-base.html"` → `start "" "%~dp0视觉资料库\\styles-overview.html"`。
- **中文**：仅在 `echo`/`REM` 中出现，且开头必须 `chcp 65001 >nul`，UTF-8 无 BOM。
- **验证限制**：沙箱禁调 `cmd.exe`，无法双击复现；以字节级 CRLF 校验 + 单独跑通 Python 逻辑作为验收证据。

## 图片缺失·根治方案（2026-08-17）
- **根因**：弹窗主图 `galImg` 是复用固定元素，旧兜底 `_imgBroken` 一旦失败就 `visibility:hidden` + 插占位块且永久残留 → 之后所有弹窗打开复用同一隐藏元素 → 全缺失。
- **彻底修法（kb_core.py）**：
  1. 远程图同步时落地本地：`_download_gpt_image()` 下载 GPT 模板的 Twitter 图到 `视觉资料库/GPT提示词库/twitter图片/`（按文件头校验真图、URL-md5 去重、失败回退）。
  2. 兜底改为自包含 SVG：所有 `<img>` 加 `onerror="this.onerror=null;this.src=_ph();"`，`_ph()` 返回内联 SVG 占位。**不隐藏元素、不插节点**，杜绝中毒 bug。旧 `_imgBroken` / 全局 error 监听 / `.img-ph` CSS 已移除。
- **验收**：融合库 309 引用全本地、0 远程、0 真实坏图、0 base64；表格页 224 全本地、0 坏图；两页均含 `_ph` SVG 兜底。
